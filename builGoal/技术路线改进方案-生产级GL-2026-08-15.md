# 技术路线改进方案与未来技术安排（面向长期生产级应用）

> 版本：v1.0（提案）  
> 日期：2026-08-15  
> 基线：《技术文档-AI智能体输入法.md》v0.6（2026-08-13）+ 附录 C.3 门禁实测（2026-08-15，487 项全绿）  
> 性质：**增量改进提案，不推翻 v0.6 已锁定决策（D1–D26）**；本文聚焦"从功能完备到长期生产级"的差距闭环与阶段化路线。  
> 读者：工程团队、产品决策层、安全评审

---

## 0. 定位与总纲

v0.6 基线的功能面已大幅超前（七层感知漏斗、动作程序、技能健康度、本地 ONNX OCR、.owflow 工作流、Goal/Plan 编排、插件市场治理骨架、云执行 v0.2 均已落地），但"生产级"包含一组功能验收不覆盖的维度：**持续可运维、可升级、可防御、可观测、可回滚、可合规**。本文按十个领域给出改进方案（§2），再给出 v0.7 → v1.0 → v2 → v3+ 的阶段化技术安排（§3）与治理机制（§4）。

改进总纲（五条原则）：

1. **先把"常驻、长时、并行"做稳，再扩功能面**：本产品是常驻桌面服务，长时运行下的内存/句柄/数据库稳定性优先于新能力。
2. **一切对外契约（HTTP/SSE/插件 manifest/技能包/工作流 DSL）必须有版本与弃用政策**：146 条路由已是事实契约面，没有版本治理就不敢改，也就无法演进。
3. **安全左移 + 红队常态化**：Auto-review 与注入防护已落地，需升级为"有指标、有回归、有对抗语料库"的安全工程。
4. **外部依赖项验收前置**：C.4 中所有"需要外部数据/环境"的验收项（STT 语料、QQ 实机、ONNX↔云 OCR 一致性）应转为常态化夜间/周度任务，而不是一次性补测。
5. **数据是用户资产**：备份、迁移、导出、销毁、加密是产品能力，不是运维脚本。

## 2. 分领域改进方案

### 2.1 A. 代码组织与架构演进

**A1. crate 拆分（对应 P1）**

把 `owo-agent-core` 按稳定边界拆为 workspace 子 crate（顺序即依赖方向，自底向上）：

| 新 crate | 内容（现有模块） | 边界规则 |
|---|---|---|
| `owo-types` | error.rs、公共 DTO、事件枚举、AgentId/SessionId 强类型 | 零 IO、零 tokio 依赖 |
| `owo-protocol` | JSON-RPC/SSE 事件 schema、openapi 片段、版本常量（扩展现有 owo-agent-protocol） | 只依赖 owo-types |
| `owo-store` | sqlite_store、session 持久化、audit、trace 落盘、migrations | 唯一允许直接碰 SQLite 的 crate |
| `owo-gateway` | gateway、provider 适配、用量/预算、语义缓存 | 网络出站点唯一 |
| `owo-perception` | perception、accessibility、ocr/onnx_ocr/paddle_ocr、vision、platform、scene、locate、window_template、element_registry | 平台 API 出站点唯一 |
| `owo-automation` | action_program、assert、executor、computer_use/computer_task、injection | 依赖 perception；SendInput/CGEvent 唯一入口 |
| `owo-learning` | learn、observe、memory、skill*、share_skill、whitelist | |
| `owo-orchestration` | workflow、goal、plan、automation（定时）、cloud_exec | |
| `owo-agent-core`（保留） | agent loop、tools、context、permissions、subagent、skill 装配、autoreview | 只做装配与循环 |

收益：并行 Agent 协作冲突面缩小（配合 AGENTS-COORD 按 crate 认领）；编译增量变小；对外发布 SDK 时可按 crate 裁剪。
验收：`cargo tree` 无环；`lib.rs` 仅 re-export；既有 487 测试不迁移语义仅迁移位置；clippy/fmt 门禁不变。

**A2. 统一错误分类（Error Taxonomy）**

`error.rs` 升级为分层错误码：`域/原因/可恢复性`（如 `gateway/rate_limited/retryable`、`permission/denied/fatal`）。HTTP 层映射稳定错误码 + `retry_after`；SSE 事件携带同一码表。这是 API 版本化（P4）的前提。

**A3. 事件与负载 schema 版本化（对应 P4）**

- 所有 SSE 事件首字段 `v: 1`；`/openapi.json` 增加 `x-owo-api-version`；
- 插件 manifest、`.owskill`、`.owflow` 的 JSON Schema 从代码生成并发布到 `/schemas/*.json` + 版本化目录（导入时按 `schemaVersion` 选择校验器，旧版本只读兼容 N-1）；
- 弃用政策：路由/事件变更走 RFC（见 §4），弃用期 ≥ 2 个 minor 版本，期间响应带 `Deprecation` 头。

### 2.2 B. 可靠性与韧性工程

**B1. 常驻服务自愈（对应 P3）**

- 核心服务内嵌心跳与自检循环（每 60s：SQLite 可写、模型网关可 dial（可选）、磁盘余量、句柄数、RSS）；异常分级：告警（诊断面板红点）/ 降级（停后台任务保主链路）/ 自愈（重启 worker、重建 SSE hub）。
- Tauri 壳对子进程增加 supervisor：崩溃自动拉起 + 指数退避 + 连续 3 次失败转人工提示；会话恢复沿用现有 resumeToken。
- Windows 服务化选项：`owo-agent --install-service`（当前用户级），开机自启从注册表 Run 升级为可选 Task/服务，规避"Explorer 未启动时托盘不可用"。

**B2. SSE/长任务语义规约**

- 每个事件流带单调 `seq`，断线重连以 `Last-Event-ID: seq` 续传（cloud SSE 已有历史重放，推广到 `/perception/events`、turn 流）；
- 背压：hub 每订阅者有界队列（如 1024），溢出策略 = 丢弃可合并事件（进度类）+ 保留关键事件（审批请求）；
- turn/工作流/Goal 运行幂等键：`Idempotency-Key` 头，重试不重复执行写操作（cloud_exec 已做任务级恢复，补到 HTTP 提交面）。

**B3. 长时稳定性验证**

- 新增 soak 测试：模拟面跑 8h（每 30s 一轮"感知→定位→执行→验证→学习"），断言 RSS 增幅 < 10%、句柄数平稳、SQLite 体积符合保留策略、无任务卡死（借 watchdog 断言）；
- 每次发布前跑 1h 短 soak，soak 进 CI nightly（见 2.5）。

**B4. 混沌与故障注入**

- 对 workflow/goal/cloud_exec 三个编排层做故障注入单测：模型网关 5xx/超时/半开流、MCP 子进程被 kill、SQLite BUSY、磁盘满、审批超时；断言状态机落到定义过的失败态且可恢复（retry/rollback/ask user 三选一），不允许"卡 Unknown"。

### 2.3 C. 安全工程

**C1. 凭据管理升级（对应 P5）**

- Provider `apiKeyRef` 落地：Windows Credential Manager / macOS Keychain 存 API Key；环境变量保留为开发模式；`settings.json` 永不落密钥（现状已守，转成契约测试断言）；
- 云执行 token（OWO_CLOUD_TOKEN）同样入凭据库；
- 新增 `/diagnostics/secrets`：只显示"哪些凭据已配置/来源/最近使用时间"，不回显内容。

**C2. 审计日志完整性**

- 审计条目增加哈希链：`prev_hash + canonical(entry) → hash`，写 SQLite 与每日摘要文件；
- 设置页提供"导出验证报告"（重放校验链），发现断链即红条告警——审计是本产品安全叙事的根基，防本地篡改是最低要求；
- 审计保留策略：在线 90 天 + 归档（zip，用户可控删除）。

**C3. 供应链安全（对应 P5）**

- 仓库内：`cargo deny`（许可证 + advisory）、`cargo audit`、npm 侧 `npm audit`（TS SDK/桌面）入 CI；依赖最低版本策略与 lockfile 强制；
- 发布物：SBOM（cargo cargo-shear + cyclonedx 输出）、安装包 Authenticode 签名（Windows）/ notarization（macOS），updater manifest 与签名公钥轮换流程；
- 模型/OCR 三件套等随包资源：下载脚本改为带 SHA-256 清单校验（现 scripts/download-*.ps1 直接信任源）。

**C4. 对抗性安全回归常态化**

- 把 v0.5.3 的 20 条注入样本升级为版本化对抗语料库 `tests/adversarial/`（目标 ≥200 条：注入、越权话术、审批钓鱼、工具描述投毒、MCP 恶意 server、.owskill/.owflow 恶意包、zip-slip 变体）；
- 指标化：Auto-review 拦截召回 ≥ 99%（对齐 Codex 口径）、误放行 0、误报率 < 2%；每次模型/策略变更跑对抗门禁；
- 每季度一次内部红队演练（模拟 GhostApproval 类社会工程 + 插件越权 + computer-use 误操作链），输出修复项进 backlog。

**C5. 插件与执行隔离收尾**

- 插件：工具级热卸载已做 → 补进程级（kill 子进程 + 资源回收 + 崩溃计数熔断）；WASM isolate 路线按 v0.6 保留，但先以"Node 子进程 + 能力 API + 权限"为生产基线并写入威胁模型；
- 本地执行：AppContainer/Job（Windows）与 sandbox-exec（macOS）从技术栈表落为实现——`shell.exec` 默认进 Job（内存/CPU/句柄上限 + 网络禁用可选），越权写盘由 OS 拦截并产生审计（当前是应用层校验）；
- computer-use：任务级审批已有 → 增加"执行期屏幕录像（帧级快照，任务结束保留 7 天，用户可关闭/导出）"作为审计回放材料；敏感面熔断规则版本化（密码/支付/验证码清单可更新）。

### 2.4 D. 数据与存储工程

**D1. SQLite 迁移框架（对应 P6）**

- 引入用户版本表 + 顺序迁移脚本（rusqlite `user_version`），禁止隐式 `ALTER`；启动时迁移 + 迁移失败自动回退到只读模式并提示导出；
- 破损恢复：启动检测 `PRAGMA integrity_check`，异常时引导"备份 + 新库重建 + 导入最近会话归档"。

**D2. 备份与数据权利（对应总纲 5）**

- 设置页"数据"区：一键备份（zip：index.db + sessions + skills + workflows + settings，排除缓存/模型）、定时备份（保留 N 份轮转）、恢复；
- 导出：会话（已有 md/html）、技能包、工作流、记忆观察记录各为标准格式；**全部数据一键导出 + 一键删除**（合规底线）；
- 学习样本与情景记忆：落盘加密（AES-GCM，密钥由 OS 凭据库派生）——兑现 v0.6 §7.6 "本地加密" 承诺；安全删除（覆写）可选。

**D3. 容量与归档**

- trace/审计/memory 已有滚动清理 → 补会话消息与附件归档（>6 个月转冷文件，可搜索但延迟加载）；向量/FTS 索引重建命令（`owo-agent reindex`）+ 增量索引健康度指标。

### 2.5 E. 质量工程与 CI/CD

**E1. 流水线（对应 P2）**

| 流 | 触发 | 内容 | 门禁 |
|---|---|---|---|
| PR 流 | 每次 push | fmt + clippy + cargo test（快集）+ 路由契约 + TS SDK typecheck/build/test + 受影响 crate 单测 | 全绿才可合 |
| Merge 流 | main 合并 | 全量 test + openapi/路由一致性 + 桌面面板接口矩阵（33 项非 404 自动化）+ 打便携包自检（/health + onnx_models_present） | 产物入库（tagged） |
| Nightly | 每晚 | soak 1h + 混沌注入集 + sim-regression + skill-gate + 对抗语料门禁 | 失败开 issue 阻塞发布 |
| Weekly | 每周 | 真模型 eval-gate（≥20 任务，阈值 0.8）+ 红队样本新批次 + 依赖审计 + SBOM 更新 | 报告进决策日志 |

平台矩阵：Windows x64 必跑；macOS arm64 从"编译 + 协议层测试"起步，随 2.7 推进到桌面链路。

**E2. 测试深化**

- Property-based：`proptest` 覆盖 action_program 解释器（随机合法程序 → 不变量：步数上限、敏感面必熔断、回滚点单调）、workflow 编译（DSL → program 保持语义）、share_skill 导入（zip-slip fuzz）、token 估算单调性；
- Eval 扩容：20 → 100 任务（分层：代码 30 / 桌面自动化 30（模拟面）/ 文档+工作流 20 / 多轮上下文 20），每任务记录成本/延迟分位，形成发布质量看板；
- Flaky 治理：测试重跑统计，>1% 失败率测试隔离到 quarantine 集并限期修复。

**E3. 性能回归（对应 3.3 预算）**

criterion 基准：工具调度往返、权限求值、locate 打分、SQLite 写放大、SSE 每秒事件数、上下文压缩耗时；nightly 与上一发布版对比，p95 劣化 >20% 阻塞发布。IPC p95（实测 1.26ms）与面板唤起 p95 转自动化（Playwright 驱动 Web 壳）。

### 2.6 F. 模型网关与成本治理

- **成本归集**：usage 记录到 (session, workflow_run, goal_step, tool) 维度，`/usage` 支持按维度过滤 + 周期报表；预算从"全局上限"细化为"每会话/每工作流可配 + 硬熔断"（超限停轮并请求用户加额，非静默失败）；
- **回退链**：agent 路由 Provider 故障时按 `强模型 → 次选云 → 本地` 显式降级，降级事件上屏 + 审计（用户永远知道当前脑子是谁）；
- **语义缓存**：工具结果去重已有 → 补"相同任务前缀的 embedding 相似缓存"（可关），命中率入 usage 报表；
- **Provider 质量回归**：每周 eval 按默认 Provider 出成功率/成本/延迟，模型升级（厂商侧变更）可被察觉。

### 2.7 G. 平台与国际化路线

- **macOS 工程化**（对应 P9）：按已有《macOS 支持规划》文档转里程碑——phase1 协议层/CLI 全绿（无桌面）；phase2 文本注入（CGEvent）+ 感知（AX API）+ 打包签名公证；phase3computer-use（v2 节奏）；
- **i18n**：工作台/CLI 文案抽离（zh/en 先行），错误码表带本地化文案；时间/数字本地化；
- **无障碍**：工作台键盘全操作 + 高对比度（产品自身应过自身倡导的可达性标准）。

### 2.8 H. 发布、运维与支持

- **版本与通道**：semver；通道 stable / beta / dev，updater 支持通道切换与灰度（按 cohort 百分比放量，失败率超阈值自动暂停——latest.json 增加 cohort 字段）；
- **诊断包**：`owo-agent doctor --bundle`：脱敏日志（凭据/内容类字段过滤）+ 配置 + 版本 + 健康检查结果 + 最近 trace 元数据，用户主动导出供支持；
- **可选遥测**：默认关，显式开启；只上报聚合指标（功能使用计数、错误码分布、性能分位），绝不含内容/上下文样本；退出随时可撤；本地优先原则下遥测与商业承诺（8.x）对齐写进隐私声明；
- **支持流程**：GitHub Issue 模板（bug 含诊断包指引）、版本升级已知问题公告、安全漏洞披露政策（SECURITY.md + 90 天协调披露）。

### 2.9 I. 开发者体验与生态

- **TS SDK GA**：发布 npm（由 openapi.json 生成），带版本化发布流程与 breaking change 政策；补 React hooks 示例（SSE 订阅/审批交互）；
- **Schema 发布**：`/schemas` 提供 manifest/.owskill/.owflow JSON Schema + VSCode 插件（校验 + 补全），降低生态作者出错率；
- **插件脚手架**：`owo-agent plugin new`（模板 + 本地测试 runner + 打包签名工具复用 plugin-sign）；文档站（架构/契约/安全要求/审核标准）；
- **示例仓库**：官方 2 示例插件 + 2 示例工作流 + 1 示例 MCP 桥接，纳入 Merge 流门禁防 API 漂移。

## 3. 未来技术安排（阶段化路线）

> 原则：每阶段有**准入条件**（上阶段退出标准）与**退出标准**（可验证指标）；不满足不进入下一阶段。与 v0.6 §12 五支柱的映射在每阶段标注。

### 3.1 v0.7「生产化加固」周期（建议 6–8 周）

目标：把现有功能面钉牢，为 v1.0 对外做准备。

| 工作项 | 对应差距 | 退出标准 |
|---|---|---|
| crate 拆分 + 错误码表 | P1 | workspace 多 crate，测试全绿，对外 API 不变 |
| CI 四流建立 + Windows/macOS-phase1 矩阵 | P2 | PR/Merge/Nightly/Weekly 全自动，产物带 SBOM |
| SSE seq 续传 + 背压 + 幂等键 | P3 | 断线重连零事件丢失（注入测试）；重复提交零重复写 |
| SQLite 迁移框架 + 备份/恢复/一键导出删除 | P6 | 升级演练：0.6 库 → 0.7 库自动迁移；备份恢复端到端 |
| 凭据库接入 + 审计哈希链 + 供应链门禁 | P5 | settings.json 无密钥断言；审计断链可检测；CI 出 SBOM |
| 对抗日测语料库 v1（≥200 条）+ 指标 | P5 | 注入拦截 ≥99%、误报 <2% 入 Nightly |
| soak + 混沌注入集 | P3 | 8h soak RSS < +10%；编排层无卡死态 |
| 性能基准 + 发布看板（成本/成功率/延迟分位） | P12 | criterion 门禁生效；eval 100 任务周报 |
| 外部验收常态化 | P8 | STT 语料/O 端到端/QQ 实机/OCR 一致性 四项进 Weekly |

### 3.2 v1.0「对外发布」周期（v0.7 退出后，建议 8–10 周）

目标：第一个可对外承诺 stable 的版本（对齐 v0.6 §9 原 M3 内涵 + §3.1 v1 清单收尾）。

- **功能收尾**：插件进程级隔离 + OS 级执行沙箱（AppContainer/Job）实证；computer-use 执行期录像审计；本地执行默认全兜底（无云 Key 也能完整用：本地模型分级 + 明确能力说明）；
- **生态起步**：TS SDK 上 npm、Schema 发布、插件脚手架、官方示例仓、文档站、SECURITY.md；
- **平台**：macOS phase2（注入/感知/打包公证）达到与 Windows 同级验收；
- **发布机制**：stable/beta 通道 + 灰度 + 自动暂停 + 诊断包 + 可选遥测（默认关）；
- **商业底座**：许可条款（Apache-2.0 + 商业授权边界）、隐私声明、第三方许可清单发布；
- 退出标准（示例）：全新机器安装 → 30 分钟内完成"首个任务"成功率 ≥95%（引导样本 20 人次）；stable 发布 4 周内无 P0 回滚事件；updater 灰度放量 100% 无异常。

### 3.3 v2「助手化 GA」周期（对齐 v0.6 §12 支柱 1/2/4，建议 2–3 季度）

前置：v1.0 退出 + 云执行生产方案定案。

- **云执行生产化（P7 定案）**：容器编排（托管 K8s 或 Firecracker/gVisor 级隔离）、凭据托管（Vault/云 KMS，任务注入式短期凭据）、配额与计量计费、任务间网络策略、区域选择（数据驻留）；退出标准：100 并发任务 24h 稳定、任务隔离渗透测试通过、diff 回传与 revert 全链路审计；
- **`.owflow` GA**：MockBackend 沙箱 → 真实执行面（感知/定位/动作/插件/MCP 混编）+ 触发器全量（定时/前台/剪贴板/语音/上游完成）+ 回滚点全类型（文件/注入/跨应用）；退出标准：12 个真实生产力工作流（报销/周报/数据搬运等）连续 4 周成功率 ≥90%，失败全部落在定义过的失败态；
- **主动生产力 v1（支柱 2）**：多信号意图打分（本地小模型）+ 建议卡片 + 三级信任模型 + 防打扰场景抑制；退出标准：建议接受率与打扰投诉率双指标达基线（内测 ≥50 人）；
- **记忆/知识底座（支柱 3 前置）**：向量 + FTS 混合检索 GA、按任务/应用/时间/结果结构化过滤、本地 embedding 默认；
- **语音入口 GA（支柱 4）**：STT WER <5%（自然语料）、语音→意图→确认→执行链路；
- **市场 GA（v0.6 D10）**：公开插件市场（提交/审核/签名/更新/分成）+ 团队技能共享只读预览；
- **多格式笔记 v1 GA（v0.6 M4c 延续）**：块树编辑器桌面化 + Yjs 单机离线 + MD/HTML/画布往返零丢失（100 文档矩阵）。

### 3.4 v3「系统化」周期（支柱 2/3/4 深化，依赖 v2 数据与模型能力）

- 个人知识图（实体 + 关系 + 时间线，本地图库 + 混合检索 + 引用可追溯生成）；
- 多信号意图预测从"建议"升级为"可授权自动"（分级授权治理框架：低提示/中审批/高二次确认+熔断，全部可审计回放）；
- 统一自然语言入口收敛（桌面/悬浮球/CLI/输入法若已启动——输入法仍受 10.1 前置条件约束）；
- CodeAct 式动作折叠（评估：把多步工具调用编译为可执行代码块，目标延迟 -30%/token -40%，先在 workflow 执行器试点）；
- 端到端加密同步（CRDT + 中继，Sync 商业化）。

### 3.5 v4「协作化」（支柱 5）

团队空间（组织/项目/成员分级）、工作流版本评审回滚、共享前强制脱敏检查、组织级审批与审计汇总、市场团队板块、企业 SSO/审计导出 API。

### 3.6 持续线（贯穿所有阶段）

- 对抗语料与红队：季度节奏，指标只升不降；
- 依赖与模型生态跟踪：MCP 规范版本、Agent Skills 标准、A2A 落地形态每季度评审一次，决定采纳/观望（写入决策日志）；
- 数据规模压力线：会话 10k 条 / 技能 500 个 / 工作流 200 个 / 索引 10 万块的容量演练每半年一次。

## 4. 治理机制（让路线可执行）

1. **决策日志**：延续 D1–D26 编号，本方案各项如被采纳，登记为 D27+（例：D27 crate 拆分、D28 API 版本与弃用政策、D29 凭据库、D30 审计哈希链、D31 遥测默认关）。改动已锁定决策必须回决策层。
2. **RFC 流程**：影响对外契约（HTTP/SSE/manifest/.owskill/.owflow/TS SDK）的变更需轻量 RFC（动机/方案/兼容性/迁移），48h 评审窗口，拒绝也留痕。
3. **契约变更三同步**（强化 AGENTS.md 既有规则）：代码 + `tests/route_contract_tests.rs` + `/openapi.json` + TS SDK 四者同一 PR 内一致，CI 强制。
4. **发布号令**：Nightly/Weekly 门禁绿灯 → RC（beta 通道 3 天）→ stable 灰度（10%→50%→100%，失败率阈值自动暂停）→ 版本公告（含已知问题/迁移指引）。
5. **并行 Agent 协作升级**：crate 拆分后 OWNERSHIP 按 crate 粒度认领；`lib.rs` 类聚合文件改动强制 `cargo check` 前置（沿用现行规则）。

## 5. 风险登记（新增项，并入 v0.6 §10）

| 风险 | 等级 | 应对 |
|---|---|---|
| 生产化投入挤占功能迭代，错失窗口 | 高 | 分层：P1–P6 为不可协商项；功能项按阶段准入排他，避免双线都慢 |
| 拆 crate 引入回归 | 中 | 纯移动 + 门禁不变 + 一次一 crate；对外 API 快照测试先行 |
| 审计哈希链/加密影响性能 | 中 | 批量落盘 + 后台摘要；基准门禁看守 |
| 灰度/updater 缺陷导致无法升级 | 高 | updater 自举回滚（旧版本可拉起修复通道）+ 通道级 kill-switch |
| 云执行定案延误拖累 v2 | 中 | v2 各子项解耦，云执行可后置；MockTransport 契约已隔离 |
| 遥测被误解为违背本地优先 | 中 | 默认关 + 聚合级 + 隐私声明前置 + 一键关闭；上线前公示数据字典 |
| 对抗语料维护成本 | 中 | 语料生成半自动化（模板 + 变体），红队输出直接回流语料库 |
