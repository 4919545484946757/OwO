# 技术路线完成度审计（v0.3 → v0.4 起点）

> 日期：2026-08-12 ｜ 审计对象：`技术文档-AI智能体输入法.md`（v0.3） ｜ 依据：`agent-sdk/ACCEPTANCE.md`、代码与测试、真实模型实测记录

## 结论

**v0.3 技术路线没有全部完成，但 M1/M2 主体已完成并通过验收。**

已完成的都是“SDK 核心 + 本地闭环”部分；未完成的是 M3 的桌面工作台/OS 级沙箱/文本注入/独立审批模型，以及 M4 的云执行/市场/笔记/computer-use。这与 v0.4 续写计划“现状盘点”一致：v1（M1/M2 主体）已完成，v0.4 从桌面端 + 技能包 + 全域感知 + 操作学习继续。

## M1/M2 验收对照

- M1：CLI 读→改→测→审批→审计闭环 ✅；越权拒绝 + 审计 ✅；HTTP API 全通 ✅；IPC p95 650µs（<5ms）✅；MCP stdio 接入 ✅。
- M2：AGENTS.md 恢复后仍生效 ✅；Skills 热加载 ✅；子代理回传 ✅；压缩规则保留回归 ✅；eval ≥20 用例 ✅；trace 回放 ✅。
- M3：沙箱加固 ⬜、独立审批模型 ⬜、Tauri 桌面 ⬜、文本注入 ⬜、插件 SDK ✅（含示例插件）。
- M4：云执行/公开市场/多格式笔记/computer-use ⬜ 未开工。

## 与 v0.4 的关系

v0.4 续写计划已把上述缺口收敛为三条主线：桌面工作台（P1）、全域情景感知 + 语音（P2）、操作学习 + 主动建议（P3）。本审计确认：

1. SDK 核心语义稳定，v0.4 桌面端可复用同一 HTTP/SSE 契约，不需要改 loop/权限/会话。
2. 需要补的 SDK 侧地基：用量统计、v0.4 设置组（stt/explore/proactive/skills/whitelist）、白名单、情景模型、学习录制与主动建议、内置技能包校验、新 HTTP 接口。
3. 输入法融合（v0.5+）维持“不实施”，满足 v0.4 计划第 10 节前置条件后再评审。
