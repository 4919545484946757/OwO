## 1. 总体评判：路线是否有问题

### 1.1 结论先行

**大方向正确，四条主干决策与业界收敛一致，无需推倒；但存在 6 个结构性风险点，其中 2 个（学习无闭环、手工管线天花板）若不在 v1 前启动补救，会在 v2"助手化"阶段变成天花板。**

与业界收敛一致、应坚持的决策：

| 决策 | 业界印证 | 判定 |
|---|---|---|
| Harness-first（模型无关、审批分离、本地优先） | Claude Code / Codex / OpenCode 竞争焦点已从模型转向 Harness 工程 | ✅ 正确且是护城河 |
| 结构化感知优先（UIA/DOM 先于像素） | Claude computer use 同样 accessibility-tree 优先、screenshot 兜底 | ✅ 正确，比纯 VLM 路线更快更稳 |
| 审批与主 Agent 分离（Auto-review 式） | Codex Auto-review、Claude Auto Mode 均已验证 | ✅ 领先于多数开源实现 |
| 技能包/工作流固化（.owskill/.owflow） | Voyager 技能库、Agent Skills 标准的思路同源 | ✅ 正确，"确定性固化层"价值随模型波动免疫 |
| 放弃输入法路线 | 与"Agent 表面层"大趋势不冲突，语音/悬浮球可替代 | ✅ 合理（10.1 前置条件机制保留即可） |

### 1.2 六个结构性风险（按严重度排序）

| # | 风险 | 根因 | 后果 | 补救窗口 |
|---|---|---|---|---|
| R1 | **学习系统无执行反馈闭环**：`generalize_traces` 只做多轨迹编辑距离对齐 + 变量推断（纯模仿学习），失败轨迹除健康度计数外不产生模型/策略改进 | 学习算法栈停留在统计归纳 | v2 主动生产力所需"越用越好"不成立；技能库只会退化不会进化 | v1.0 前启动支线，v2 主线 |
| R2 | **感知管线手工权重天花板**：`locate.rs` 是固定证据权重表 + 阈值规则；视觉 grounding 只做旁路证据，无本地 GUI grounding 模型 | 手工规则无法覆盖长尾界面（自绘/游戏/远程桌面/Canvas 应用） | 复杂应用成功率骤降；每类新界面都要人肉调权 | v1.0 前支线验证 |
| R3 | **本地模型算力路线缺失**：本地验证停留在 CPU 3B（llama3.2:3b 单工具轮 64.8s，复杂任务超时）；无 NPU/GPU 路线，而 2026 年 Copilot+ PC 已普及 40+ TOPS NPU | 硬件基线（3.3 节）写死于"无独立 GPU" | "本地优先"承诺在多模态时代落空：本地 VL/grounding/STT 同时跑不动 | v1.0 起 |
| R4 | **评估缺 GUI Agent 基准**：evals 是 20 个自造任务；未对接 OSWorld / WindowsAgentArena 类标准化基准，owo-sim 模拟实验台未被用作轨迹工厂 | 评估体系与研究对象（桌面 Agent）错位 | 无法证明"业界可比的成功率"，也无法产生训练数据 | 立即（成本低收益高） |
| R5 | **Python 生态缺位**：SDK 只有 Rust + TS；Agent 开发者/研究者主力在 Python（Pyodide/PyO3 缺位） | 客户端形态选择时未覆盖 | 生态冷启动雪上加霜；R4 的研究型贡献者进不来 | v1.0 |
| R6 | **感知为拉取式轮询**：UIA 树/OCR 按调用全量抓取，UIA AutomationEvent、WinEventHook 事件驱动源未接入主链路（observe.rs 部分接入但执行链路仍是拉取） | 实现惯性 | 感知延迟与 CPU 占用高，v3"预判下一步"需要的连续世界状态流不存在 | v2 前 |

另有 3 个次级问题（不阻塞但应排期）：审批疲劳无分级自治机制（每步 confirm 会随工作流变长而不可用）；多模态输出弱（只有文本+文件，无标注框/图表/回放类"可视化证明"）；A2A/computer-use 工具 schema 等协议对齐停留在"提及"层面。

## 2. 逐层技术审查与更优做法

### 2.1 感知层：从"拉取式管线"到"屏幕流 + 学习型融合"

**现状**：调用时全量抓 UIA 树/截图 → OCR → 固定权重融合。优点是确定性好、可审计；缺点是每次感知都是冷启动，且融合权重不可学习。

**更优做法（三层递进，均可增量落地）**：

1. **感知服务化（屏幕流）**：常驻 perception service 维护 SceneGraph 增量更新——UIA `AutomationEvent`（Focus/PropertyChanged/StructureChanged）+ WinEventHook（前台/窗口变化）事件驱动，帧差触发增量 OCR（只识别变化区域），OCR 结果按区域缓存失效。感知从"每次 200–800ms 冷抓"变为"查询即读内存 <5ms"。SceneGraph 的跨帧稳定 ID 基础设施已具备，只差把更新源从拉改成推。
2. **学习型融合排序**：`locate.rs` 的固定权重表替换为轻量学习排序器（特征：各源置信度、几何一致性、历史命中、文本相似度 → 输出校准概率）。训练数据零成本：现有 `template_hits`/`prior_hit`/执行成败记录天然构成 (query, candidates, clicked, success) 监督对。保留规则表为冷启动默认值与回退。
3. **本地 GUI grounding 模型兜底**：接入 ScreenSpot 类开源 grounding 权重（UI-TARS-grounding / OS-Atlas-7B / SeeClick，ONNX 量化后 NPU/GPU 可跑），用于 UIA/DOM 双失灵的自绘界面；配合 Set-of-Marks（SoM）标注——在截图上编号候选框让 VLM 选择，把开放 grounding 变成选择题，小模型也能用。grounding 结果按 5.8 原则只作证据，与 OCR 交叉验证。

**判定**：现架构方向对，但必须完成"拉→推"与"规则→学习"两次升级，否则 v2 主动感知（预判）无数据流基础。

### 2.2 执行层：动作优先级应显式化为"可靠性阶梯"

**现状**：executor 已有 UIA InvokePattern 直驱（executor.rs:457）+ SendInput 兜底，方向正确；但优先级选择散落在实现里，未上升为契约。

**更优做法**：把动作通道定义为四级可靠性阶梯，每级带能力声明与降级语义：

| 级 | 通道 | 特点 | 适用 |
|---|---|---|---|
| L1 | 语义直驱（UIA ControlPattern：Invoke/Value/Scroll/Select；浏览器 DOM ref/aria-ref） | 不需要前台焦点、可后台、可并行、无坐标漂移 | 一切可及的场景，**默认** |
| L2 | 坐标语义（UIA BoundingRect + SendInput） | 需前台，但锚点语义稳定 | L1 不可用（无 Pattern 的控件） |
| L3 | 视觉定位（grounding/OCR 中心点击） | 需前台 + 前置截图 | 自绘/远程/Canvas |
| L4 | LLM 决策动作（computer-use 工具 schema，截图→动作） | 慢、贵、不确定 | 兜底与探索 |

浏览器侧全面转向 Playwright MCP 式 aria-ref 交互（accessibility snapshot 带稳定 ref，点击=by ref 而非坐标），已被 Claude Code/主流 browser agent 验证为最稳路径。每步执行记录"所用级别"，L3/L4 占比成为界面兼容性监控指标——这个指标直接驱动感知层投资优先级。

### 2.3 学习层：最大缺口，需引入执行反馈闭环（R1）

**现状**：示范学习（多轨迹对齐→变量推断→技能包）+ 受限探索 + 健康度降级。本质是**模仿学习 + 规则固化**，失败只降级不学习。

**更优做法（Voyager/ExpeL 式经验闭环，分四步）**：

1. **轨迹资产化**：所有执行（人审批下的 Agent 执行、技能回放、示范录制）统一为带 Outcome 标注的轨迹格式（已有基础：Observation/Outcome/SkillHealth）。补：每步记录感知快照哈希、动作级别、断言结果——这是后续一切学习的燃料。
2. **失败归因**：失败轨迹不再只计数，走自动归因分类（锚点漂移 / 时序竞争 / 断言过严 / 界面改版 / 权限拒绝），归因结果决定动作：锚点漂移→触发重对齐学习；界面改版→标记技能需重录；时序竞争→插入 WaitUntil。
3. **经验蒸馏**：周期性把 (成功轨迹, 失败轨迹+归因) 蒸馏为技能包的元数据改进——前置条件集收紧/放宽、断言配方修正、锚点先验更新（先验本身就是 2.1 学习排序器的训练数据）。这一步不需要训练模型，纯数据工程，v1.0 可落地。
4. **策略优化（v2+，选配）**：轨迹积累到万级后，两条路任选：① 偏好优化路线——构造 (成功轨迹, 失败轨迹) 偏好对，对自有路由小模型做 DPO，或反馈给模型厂商 API；② 提示策略路线——用 ExpeL 式经验抽取，把失败教训写成技能包 playbook 注入系统提示。路线①需要 GPU 预算与模型权重决策，先做②。

**owo-sim 升级为轨迹工厂**：现有 QQ/浏览器模拟器 + headless 虚拟输入已具备"环境"要素，缺的是任务生成器与扰动引擎（随机改 UI 布局/延迟/文案 → 测试技能鲁棒性 + 生成合成训练轨迹）。这是全项目**杠杆率最高**的未利用资产：既出评估数据（对接 R4），又出学习数据（供给 R1），还出混沌测试（生产化方案的 B4）。

### 2.4 记忆层：从"向量 + jsonl"到"时序知识图 + 睡眠期整合"

**现状**：情景记忆 jsonl + 语义记忆向量索引 + 滚动清理。检索是单路召回。

**更优做法**：

- **时序知识图**：memory.rs 演进为实体-关系-时间三元组（参照 Zep/Graphiti 形态）：(用户, 使用, 应用X, t1..t9, 频次)、(工作流Y, 成功于, 应用X)。价值：`memory.recall("我上周怎么导出的报表")` 需要时间推理，纯向量做不到；知识图 + 向量 + FTS 三路混合检索 + LLM 重排。
- **睡眠期计算（sleep-time compute）**：用户空闲时段（已有空闲检测）执行后台整合：情景记忆→情景摘要、重复模式→候选技能（已有）、实体消歧与合并、向量索引重建、模板健康预检（已有）。把"记忆整理"从写路径挪到空闲路径，参照 Letta sleep-time 思路。
- **程序性记忆独立**：技能包（含健康度、前置条件、断言配方）就是程序性记忆，与情景/语义记忆分开治理——现状已对，明确命名即可。

### 2.5 规划层：引入"仿真预演"与分层思考预算

**现状**：goal/plan DAG + 动作程序解释器，规划是单次生成。

**更优做法**：

- **高风险预演（dry-run）**：跨应用工作流首次执行前，在 owo-sim 或"影子模式"（只感知不动作，逐步验证锚点可定位、断言可求值）预走一遍；预演通过才允许真实执行。等于给 12.6"工作流漂移"风险加了执行前闸门。
- **思考预算分档**：模型路由从"按任务类型"升级为"按难度自适应"——简单轮次直接小模型，检测到规划失败/重试/复杂分支时升级强模型 + 允许更长推理（test-time compute 旋钮）。现有 DeepSeek/强模型双路由已有骨架，加置信升级触发器即可。
- **树搜索（v3 远期）**：高风险动作用 ToT/MCTS 在世界模型（= sim 或学习到的界面动态）上展开几步候选并择优；依赖轨迹工厂先产出界面转移数据。

### 2.6 模型基建：本地优先需要一条 NPU/GPU 路线（R3）

- **分层推理目标**（2026 硬件现实）：文本路由小模型（1–4B，CPU/NPU 皆可）、GUI grounding（1–7B 量化，NPU/GPU）、VL 验证（3–8B，GPU/NPU）、STT（已有 SenseVoice）。CPU 只承担第一层；"无独显"基线修订为"无独显但 NPU 40 TOPS 可选"。
- **推理后端**：ONNX Runtime GenAI（DirectML/NPU，Windows 主线）+ MLX（macOS）；llama.cpp 保留为通用兜底。模型分发复用现有 download-*.ps1 + 便携包机制。
- **级联路由 + 置信升级**：本地小模型先答 → 置信度/自评不过 → 升级云端；配合 prompt caching（Anthropic/OpenAI 均支持）把"系统提示+技能清单+AGENTS.md"常驻前缀的成本砍掉 50%+，语义缓存已有。
- 2026 现实检查：不追求本地全闭环跑强 Agent（业界也没人做到），目标定为**"断网时感知/OCR/STT/技能回放 100% 可用，文本推理降级可用"**。

### 2.7 协议与生态：三个对齐动作（次级问题）

1. **computer-use 工具 schema 对齐 Anthropic 标准**（screenshot/click/type/scroll 的工具定义已成事实标准）——对齐后可直接换插业界 VLM/CUA 模型，不自造方言；
2. **Python SDK（PyO3 绑定）**：R4 研究者、插件作者、eval 脚本的主力语言；发布 PyPI；TS SDK 继续服务客户端集成；
3. **A2A 观察→v2 末接入**：团队工作流（支柱 5）前不投入；AG-UI（Agent-UI 事件协议）在桌面工作台重构前端时评估。

### 2.8 审批与自治：治理"审批疲劳"

**现状**：每步 confirm + high_risk_ack，工作流一长审批次数线性膨胀——这是 v2 工作流可用性的隐形杀手。

**更优做法——分级自治（earned autonomy）**：技能/工作流步骤带自治等级 `manual → supervised → autonomous`，升级条件为"连续 N 次成功 + 断言覆盖 + Auto-review 放行"，降级条件为"任何失败或断言缺失"；autonomous 级执行只记审计不打扰；涉及 inject/write/网络边界的步骤永不低于 supervised。等级迁移本身是一个显式审批事件。这与航空自动化分级（fly-by-wire 包线）同构，比"全自动/全手动"二极管更适合工作流场景。

## 3. 替代技术路线对比与选择

| 路线 | 描述 | 优势 | 致命伤 | 判定 |
|---|---|---|---|---|
| **A 现状增强**（结构化优先 + 规则融合） | 现路线持续打磨 | 确定性、可审计、已验证 | 手工管线天花板（R2），长尾界面覆盖成本线性增长 | 作为基线保留 |
| **B 端到端 VLM GUI Agent**（截图→动作大一统，UI-TARS/CUA 式） | 单模型解决感知+决策 | 通用性上限最高、零适配新应用 | 本地跑不动（R3）；延迟/成本高；不可解释→审批难落地；黑盒动作与"审批式安全"品牌冲突 | **不作为主路线**；以 L4 兜底执行器形式可插拔引入 |
| **C 神经符号混合**（结构化锚点优先 + 学习型融合/grounding 兜底 + VLM 验证 + 执行反馈闭环） | A 的骨架吸收 B 的组件 | 每个组件可独立验证/审计；上限接近 B，下限保持 A；升级路径平滑 | 工程复杂度高，需要 2.1–2.4 全套 | ✅ **推荐主线** |
| **D 确定性工作流固化**（.owflow 主导，LLM 仅异常时介入） | RPA 化 | 极致可靠、可回滚 | 智能上限低，无法处理未预定义分支 | 保留为"已验证流程的固化层"（现定位已正确） |
| **E MCP 万物 + 外部 Agent runtime**（自研只做壳与治理） | 生态寄生 | 工程量最小 | 感知/学习/审批差异化全部让渡，护城河消失 | 仅作互操作补充（现定位已正确） |
| **F OS 表面层路线**（输入法/系统搜索/通知集成） | 系统级入口 | 触达深 | 输入法前置条件未满足（10.1）；与 D5–D7 锁定冲突 | v3 表面层选项，前置条件机制不变 |

**结论：C 主线 + D 固化层 + B 作 L4 可插拔执行器 + E/F 作补充。** 这与现路线的差异只有两处实质升级：①"规则融合"→"学习融合 + grounding 兜底"；②"模仿学习"→"执行反馈闭环"。两者都不需要推翻任何已落地代码——SceneGraph/动作程序/技能包/审批全部是 C 路线的现成地基。

## 4. 前沿多模态 Agent 功能蓝图

> 按"感知 smarter / 执行 smarter / 学习 smarter / 记忆与规划 / 交互与输出 / 基建"六组，标注优先级（P0 生产差异化 / P1 下一版本 / P2 远期）与依赖。

### 4.1 感知 smarter

| 功能 | 说明 | 优先级 | 依赖 |
|---|---|---|---|
| 屏幕流服务 | 事件驱动 SceneGraph 增量更新 + 区域级 OCR 缓存（2.1.1） | P0 | UIA 事件源 |
| Set-of-Marks 标注 | 截图编号候选框供 VLM 选择，小模型可用的 grounding | P0 | 无 |
| 本地 GUI grounding | UI-TARS-grounding/OS-Atlas 量化 ONNX，ScreenSpot ≥80% 起步 | P1 | NPU 路线 |
| 像素-语义对齐 | DOM/UIA 树与截图坐标双向映射（cross-modal grounding），视觉证据自动锚定到语义元素 | P1 | 屏幕流 |
| 文档深度理解 | PDF/表格结构化解析 + 表格 VQA + OCR-free 文档模型（DocLayNet 类版面分析），支撑 docs.generate 与"数据搬运"场景 | P1 | — |
| 视频演示理解 | 用户录屏 → 动作分割与流程抽取（"看一遍就会"，见 4.3） | P2 | 轨迹工厂 |

### 4.2 执行 smarter

## 5. 技术路线安排（演进阶段 + 研究支线）

### 5.1 与既有版本节奏的衔接

生产化主线（v0.7 加固 → v1.0 对外）**不被本方案推迟**；本方案以**研究/能力支线**形式与主线并行（人力隔离，参考 AGENTS-COORD 按 crate 认领），产出按准入条件合入主线版本：

```
主线（生产化）      v0.7 加固 ──────► v1.0 对外 ──────► v2 助手化 ──────► v3 系统化
能力支线（本文）  R1 感知/执行升级 ─► R2 学习/多模态 ─► R3 闭环/知识图 ─► R4 预演/个性化
研究支线（spike）  S1 grounding  S2 NPU  S3 全双工语音  S4 世界模型  S5 视频学习
```

### 5.2 R1 感知/执行升级支线（与 v0.7 并行，6–8 周）

| 工作项 | 产出 | 合入点 |
|---|---|---|
| UIA 事件源 + 屏幕流服务 | 感知查询 p95 <10ms（内存读），常驻 CPU 占用 <3% | v0.7 末 |
| 可靠性阶梯契约化 + aria-ref 浏览器 | L1 占比 ≥70%（浏览器/办公场景），占比入监控面板 | v0.7 末 |
| SoM 标注 + computer-use schema 对齐 | VLM 兜底动作用标准 schema，可换插任意 CUA 模型 | v1.0 |
| GUI 基准 harness | WindowsAgentArena 子集 20 任务 + sim 任务生成器夜跑，成功率看板 | v0.7 末（R4 解除） |
| Python SDK alpha（PyO3） | session/turn/tool/permission 四类 API 可用，PyPI 内测 | v1.0 |
| Prompt caching | 会话成本 -40% 实测 | v0.7 |

退出标准：基准 harness 连续 4 周出数；屏幕流在 8h soak 下无泄漏（衔接生产化 soak）。

### 5.3 R2 学习与多模态支线（v1.0 周期，8–10 周）

| 工作项 | 产出 |
|---|---|
| 轨迹资产化 + 失败归因 | 统一轨迹格式 v1；归因分类覆盖 ≥90% 失败样本 |
| 学习型定位排序 | 固定权重表 → 学习排序器，locate top-1 命中率 +10pp（基准集验证），规则表回退保留 |
| 本地 grounding 接入主链 | L3 视觉定位走本地量化模型，自绘界面基准成功率 ≥60%（冷启动口径） |
| 分级自治审批 v1 | manual/supervised/autonomous 三级 + 迁移审批事件；长工作流审批次数 -70% |
| 可视化证明 | 标注框截图/执行回放/图表生成进工作台 |
| 文档深度理解 | 表格 VQA + 版面分析进 docs.generate 与"数据搬运"工作流 |
| S2 NPU spike / S3 语音 spike | NPU 上 7B 量化 grounding 可用性结论；云 realtime 语音链路 demo |

退出标准：归因分类器上线后技能库整体成功率环比上升；分级自治下无 P0 越权事件（对抗门禁验证）。

### 5.4 R3 学习闭环与知识图（v2 前半，对齐 .owflow GA 与主动引擎）

- 经验蒸馏全量上线（技能元数据自动改进闭环）；
- 时序知识图 + 三路混合检索 GA（memory.recall 时间推理类查询 top-5 ≥0.8）；
- 思考预算自适应（级联 + 置信升级 + test-time compute 旋钮）；
- 影子模式预演接入 .owflow 首次执行闸门；
- CodeAct 退出试点判定（token/延迟收益 ≥30% 则 GA）；
- S4 世界模型 spike：用轨迹工厂界面转移数据训练轻量动态预测，高风险动作 1 步预演可用。
- 退出标准：12 个真实工作流 4 周成功率 ≥90%（对齐 v2 口径）且其中 ≥3 个依赖经验蒸馏修复的技能。

### 5.5 R4 深水区（v2 后半–v3）

偏好优化闭环（DPO/playbook 双路决策）、看视频学技能、移动表面（Android MCP）、个性化偏好模型、世界模型 MCTS 预演、本地全双工语音、悬浮球表面、A2A 团队互操作、（10.1 前置条件满足时）输入法表面重启评估。

### 5.6 研究支线治理（Spike 机制）

| Spike | 时盒 | 成功标准 | 失败处置 |
|---|---|---|---|
| S1 本地 grounding | 3 周 | ScreenSpot-mini ≥75%（量化后 NPU/GPU） | 降级为云 grounding API 可选通道，L3 维持 OCR |
| S2 NPU 推理 | 3 周 | 7B 量化模型首 token <1.5s（40 TOPS 档） | 本地路线维持 ≤3B + CPU，重排 2.6 目标 |
| S3 全双工语音 | 4 周 | 云 realtime 端到端延迟 <800ms + 打断生效 | 维持推到谈 + 流式 TTS |
| S4 世界模型 | 6 周 | 1 步界面状态预测 top-1 ≥60%（sim 集） | 预演维持影子模式，不上 MCTS |
| S5 视频学习 | 6 周 | 10 段录屏 ≥7 段正确抽取流程骨架 | 维持结构化录制示范 |

Spike 产出一律写决策日志（D32+ 编号延续），失败也留档——避免六个月后被重新发明。
