# macOS 支持决策评审（P5）

> 日期：2026-08-13 ｜ 依据：《技术文档-AI智能体输入法.md》v0.6 D2（v1 优先 Windows 11 x64 + macOS Apple Silicon）
> 结论：**macOS 顺延至 v2，v1 交付 Windows-only**；代码层平台抽象保持（非 Windows stub 23 处），不投入 macOS 实机开发。

## 一、现状盘点

| 层 | 状态 | 说明 |
|---|---|---|
| 平台抽象 | ✅ 已具备 | `platform.rs`/`executor.rs`/`ocr.rs`/`accessibility.rs`/`stt.rs`/`perception.rs` 均含 `cfg(not(target_os="windows"))` stub（23 处），非 Windows 可编译骨架成立 |
| Windows 实现 | ✅ 完整 | 前台窗口、剪贴板序列、UIA 树、GDI 截图、SendInput 注入、OCR、窗口模板、元素注册表、动作程序执行器全部实机验证 |
| macOS 实现 | ⬜ 未开始 | CGEvent 注入、辅助功能授权（AXUIElement）、截图（CGWindowList）、本地 OCR（Vision framework）均未实现 |
| 交叉编译验证 | ⬜ 不可行 | 本机无 aarch64-apple-darwin 工具链，无法静态验证 macOS 编译 |

## 二、工程量与风险

| 项 | 风险 | 说明 |
|---|---|---|
| 文本注入（CGEvent 替代 SendInput） | 中 | API 不同但语义等价，约 1-2 天 |
| 辅助功能授权（AXUIElement 替代 UIA） | 高 | macOS TCC 授权流程 + AX 树遍历实现差异大，约 1 周 |
| 截图（CGWindowList 替代 GDI） | 低 | API 等价，约 0.5 天 |
| 本地 OCR（Vision 替代 Media.Ocr/ONNX） | 中 | 需 macOS Vision framework 桥接，ONNX OCR 可复用，约 2-3 天 |
| STT（sherpa-onnx 跨平台） | 低 | 已跨平台 |
| 执行沙箱（sandbox-exec 替代 AppContainer） | 中 | API 差异，未实现 |
| 真机验收（辅助功能授权/沙箱权限 UI） | 高 | 无 Apple 硬件无法验证 |

## 三、决策

1. **v1 交付范围 = Windows 11 x64 only**（对齐 D2 的"优先"语义，不阻塞 v1 验收）。
2. **macOS 列为 v2 候选**：进入 v2 时，工程量估计 2-3 周（含真机验收），前置条件为获得 Apple Silicon 硬件。
3. **代码约束（立即执行）**：所有平台相关代码必须保持 `cfg(target_os)` 隔离，非 Windows 分支必须有编译级 stub；新提交的 Windows 平台代码不得破坏非 Windows 编译骨架（CI 门禁若引入 macOS runner 则自动生效）。
4. 输入法融合（M6）与 macOS 无耦合；computer-use v2 的跨平台接口设计（`UiActionSource` trait）已预留。

## 四、与文档的差异说明

技术文档 D2 原文"v1 优先 Windows 11 x64 + macOS（Apple Silicon）"。本决策把 macOS 从 v1 移出为 v2，理由：
- 无 Apple 硬件，macOS 实机验收（辅助功能授权流程、沙箱权限 UI、注入兼容矩阵）不可执行；
- Windows 主线仍有大量 v1 P0/P2 工作（云端执行、TS SDK、computer-use 审批版），macOS 投入会稀释主线；
- 平台抽象已就位，macOS 顺延不产生架构返工。
