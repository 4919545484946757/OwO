# 阶段启动单：P4 首批官方插件

- 状态：P4.0 高权限插件通道已完成，待正常用户上下文集成验收
- 日期：2026-08-03

## 阶段目标

在不影响 TSF/Core 基础输入的前提下，为首批官方插件建立真实用户入口、权限与资源扩展能力。P4.0 先完成受控高权限插件通道；随后按总控路线进入字符编码转换插件 P4.1～P4.8。

## 本阶段范围

- P4.0：风险分级、能力清单、第三方/未验证包预检、逐包知情授权、权限撤销和全信任独立进程边界。
- 后续：字符编码转换首版最低闭环，以及截图、OCR、语音、文本处理、快捷键和 AI Agent 的优先级复核。

## 明确不做

- 不把插件代码加载到 TSF DLL 或 Core Service 地址空间。
- 不授予管理员、内核驱动、UAC 绕过或静默持久化能力。
- 不把安装确认当作候选链路或 Agent 的可信用户动作。
- P4.0 不同时实现每一种资源包业务处理器；先冻结并验证权限与安装/运行纵向闭环。

## 核心数据流

```text
文件选择器
→ 同快照包/manifest/信任/权限预检
→ 风险与免责告知
→ 精确 ID + 版本 + 清单摘要单独授权
→ 后端重新预检并匹配确认
→ 安全暂存与版本发布（高风险默认停用）
→ 版本绑定授权记录
→ 显式启用
→ AppContainer 或经授权的 full-trust PluginHost
```

## 验收标准

- 受信低风险路径不降级；高风险路径不能绕过摘要、免责声明或权限匹配。
- 未验证高风险版本安装后不自动启用，更新不继承授权。
- 撤销后设置中心和 PluginHost 均拒绝全信任启动。
- 全信任插件仍不继承句柄，并受 PID 绑定管道、Job、超时和进程回收控制。
- C++ Release 构建、插件契约/安装测试和 WinUI Release 构建通过；正常用户上下文补跑 AppContainer/full-trust 集成测试。

## 风险与回滚

主要风险是用户把全信任误认为细粒度沙箱，以及第三方代码直接访问当前用户数据。界面必须明确说明这一事实。回滚按 ADR 0022 禁用高风险入口和 `system.full_trust`，不影响基础输入。
