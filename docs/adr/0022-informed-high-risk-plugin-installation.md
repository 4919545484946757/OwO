# ADR 0022：P4 高风险插件知情安装与全信任执行

- 状态：P4.0 已采用
- 日期：2026-08-03

## 背景

P3C 只允许 Windows 离线信任链完整的签名包，并固定使用零能力 AppContainer。该默认路径适合普通插件，但无法承载桌面宠物、Win32 UI 覆盖、网络、外部进程、任意用户文件、屏幕/麦克风，以及字典、主题或材质资源安装等能力。开发者已批准在明确告知风险和免责后，允许用户对第三方、低安全、高风险或高权限插件逐包授权安装。

放宽安装策略不能把第三方代码加载进 TSF/Core，也不能把一次确认变成所有插件、所有版本或所有后续权限的永久授权。

## 决策

1. 保留 P3C 的受信默认通道。Windows 信任发布者且最高风险低于 `high` 的包仍走 `install`，重新验证后原子安装并激活；这个路径不接受信任降级。
2. 新增只读 `inspect-install`：从同一次有界包快照读取并校验 manifest，输出插件 ID、精确版本、规范化清单 SHA-256、发布者状态、风险等级、网络标记和权限清单。安装时重新读取包并核对清单摘要，预览与安装不匹配即拒绝。
3. 发布者分为 `trusted_publisher`、`third_party_signed` 和 `unverified_package`。未验证包在内部安装绑定中使用 64 个零字符作为“无发布者证书”哨兵；该值绝不显示为证书指纹或可信发布者。
4. `high`、`critical`、第三方签名或未验证包只能走 `install-risk`。设置中心先要求用户勾选完整风险与免责告知，再用第二个对话框对精确插件 ID、版本和清单摘要单独授权。后端要求免责声明版本、清单摘要、未受信发布者接受标志、全信任接受标志和完整 manifest 权限集合全部匹配。
5. 高风险包发布后保持停用。安装记录 schema 2 固化信任层级，授权记录 schema 2 绑定插件 ID、精确版本、清单摘要、发布者绑定、权限、同一信任层级、免责声明版本与知情确认；任一记录缺失或不一致都失败封闭。旧安装记录和 schema 1 授权仅按“可信发布者”兼容读取，不得用于第三方或未验证插件，也不隐式升级为高风险授权。更新不继承旧授权。
6. 用户可在设置中心撤销精确版本的全部运行权限。撤销会先停用插件，再原子写入零权限记录；文件和用户数据保留。`system.full_trust` 授权不完整或已撤销时，管理后端拒绝重新启用，PluginHost 也在每次启动前重新核对全部声明权限。
7. 能力集合扩展为剪贴板、输入上下文/提交/替换、网络、用户选择文件、任意文件系统、外部进程、屏幕、麦克风、UI 覆盖、桌面宠物、字典/主题/材质安装和 `system.full_trust`。需要普通 Win32 用户令牌的能力必须同时声明 `system.full_trust`，`network=true` 必须与 `network.client` 精确一致。
8. 未声明 `system.full_trust` 的进程插件继续使用零能力 AppContainer。已声明且完整获授的精确版本可在普通当前用户令牌下运行；它仍使用固定入口、`bInheritHandles=FALSE`、受限环境块、先挂起后加入 Job、随机单客户端管道、同用户令牌核对和精确子进程 PID 绑定。默认最多一个进程、每进程 512 MiB；只有声明并获授 `process.launch` 时允许 Job 内最多 8 个进程。关闭会话仍终止整个 Job。
9. 全信任表示插件实际上能够以当前 Windows 用户权限直接访问资源，平台无法像 AppContainer 一样逐项强制网络、文件或 UI 能力。权限清单用于知情告知、版本绑定、审计和启动门禁，不能被描述为 OS 级细粒度隔离。全信任插件不获得管理员提权、内核驱动或绕过 UAC 的能力。
10. `install-risk` 的确认参数是安装事务的显式契约和审计证据，不是不可伪造的运行时用户动作凭据；它不得映射为 ADR 0020 中的 `trusted_user_action`，也不开放 TSF/Core 插件调用入口。

## 结果

第三方与未验证包可以在用户明确承担风险后安装，桌宠、覆盖层、资源包和其他普通 Win32 能力有了可执行通道；安全插件的默认沙箱和受信安装路径保持不变。代价是全信任插件与用户本人拥有近似的数据访问能力，恶意插件可能导致隐私、文件、账户或持久化风险，因此 UI 必须持续显示信任层级、风险和权限，并允许撤销。

## 回滚

删除 `install-risk`/预检 UI、拒绝 manifest 中新增权限，并令 PluginHost 对 `system.full_trust` 无条件失败，即可回到 P3C 受信签名 + 零能力 AppContainer 基线。已安装的高风险版本应先停用并逐版本卸载；不得把它们静默迁移为受信插件。
