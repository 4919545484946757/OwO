# ADR 0032：当前输入会话的短期语言上下文排序

- 状态：已接受
- 日期：2026-08-09

## 决策

1. TSF 在同一焦点文本会话内保留最近一次 OwO 已提交片段，最多 16 个 UTF-16 单元，作为稳定的 Bigram 前文。切换文档、失去线程焦点或提交原始英文时立即清空，不读取应用名称、窗口标题或整篇正文。
2. 候选请求通过协议 v9 携带该短期前文。Core 在智能排序开启时叠加“短期前文 + 规范化拼音 + 候选”的本地学习分数。
3. 候选成功上屏后，反馈同时携带选择前的短期前文、实际消费的拼音片段和候选文本。部分提交会先把已提交词加入前文，再为剩余拼音请求候选，因此同一长拼音的分段选择也能获得语言上下文。
4. OWUF v3 新增三元上下文计数，并继续读取 v1 全局计数和 v2 拼音关联计数。语言上下文每次选择的增益为 `1000 + (灵敏度 - 1) × 1000`，高于拼音关联与全局词频，使明确的短语习惯能在少量选择后体现。
5. ModelHost 协议 v2 同步携带前文。合格的外部排序模型可使用“前文 + 拼音”重排；未安装、失败或超时时仍立即使用 Core 基础候选与本地学习结果。

## 限制

TSF 只掌握由 OwO 自身提交的连续文本，不抓取光标前已有正文。这样避免无提示读取宿主文档，但用户在中间通过其他方式编辑文本时，短期上下文会在焦点边界或原始输入时失效，而不是扫描正文重建。

## 回滚

关闭智能排序立即停止使用拼音关联和语言上下文分数。协议 v9 的 TSF/Core、ModelHost v2 的双方必须成套部署。旧程序不能解析 OWUF v3；回滚二进制前应导出或清除新格式用户词频。
