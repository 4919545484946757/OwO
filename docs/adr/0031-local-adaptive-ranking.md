# ADR 0031：本地上下文自适应排序与可调学习灵敏度

- 状态：已接受
- 日期：2026-08-09

## 决策

1. 用户学习同时保留全局候选计数和“规范化输入拼音 → 候选文本”计数。全局计数继续改善常用词排序；上下文计数仅在设置中的“智能排序（本地自适应）”开启时参与排序，避免同一个汉字在无关拼音中被全局过度提升。
2. 学习灵敏度为 1～10 档，默认 7。全局计数每次选择的分数增益为 `250 + (档位 - 1) × 250`，上下文计数为其两倍。档位只影响评分，不改变持久化计数。
3. `candidate_committed` 反馈携带候选文本和实际消费的原始拼音片段。TSF 只在编辑会话成功后发送；部分候选提交只学习已消费前缀，不记录剩余拼音。
4. OWUF v3 在同一校验和与原子替换边界内存储全局、拼音关联与短期语言上下文计数。读取器兼容 OWUF v1/v2；旧文件在下一次落盘时升级，不需要清空用户数据。
5. Core 同步生成基础候选并应用轻量本地排序。ModelHost 接口继续保留给许可证明确、质量验证通过的可替换排序模型；外部模型失败、超时或未安装时不影响基础输入。
6. 当前 MockModelBackend 只用于协议和流水线测试，不作为产品智能能力，也不随普通开发启动脚本启用。

## 隐私与边界

学习数据仅包含输入法内部的拼音片段、被选候选和饱和计数，不包含应用名称、窗口标题、周边正文或网络标识。关闭学习停止写入；关闭智能排序停止使用上下文分数，但保留数据以便重新启用。

## 回滚

关闭 `model_ranking_enabled` 可立即回到全局词频排序。程序仍可读取旧 OWUF v1/v2；若需要回滚二进制，应先导出或清除新格式上下文记录，因为旧程序不能解析 v3 文件。协议 v9 的 TSF 与 Core 必须成套部署。
