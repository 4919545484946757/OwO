# ADR 0022：不完整拼音补全与有界纠错候选

- 状态：P3 后体验优化已采用
- 日期：2026-08-02

## 背景

原全拼解析器能够标记末尾的不完整音节，但候选生成器会丢弃包含该标记的全部路径。因此单声母 `b`、`nih`、`zhongg` 等输入没有候选。完全无法按合法音节切分的误触、漏字、多字和相邻字母颠倒也不会进入词典查询，候选窗只能持续显示加载省略号。

## 决策

1. 不完整拼音补全解析路径末尾已有的音节前缀，不改写已完成音节。候选路径仍限制为最多 32 条，并优先保留音节更少、补字符更少的补全。
2. 当输入不存在任何完整拼音切分时，增加多音节简拼/混拼展开。2～16 字节输入可切成最多 8 个音节前缀，例如 `w+q → wo+qu`、`k+y → ke+yi`、`go+m → gou+mai/gou+ma`；每个偏移使用最多 128 条内部 Beam，发布结果仍受 32 条总上限约束。
3. 同样在无完整切分时启用最多一次编辑的纠错：相邻字母颠倒、漏一个字母、多一个字母、QWERTY 相邻键替换，以及 `l/n`、`f/h` 常见声母混淆。少于 3 字节、超过 32 字节或含显式单引号边界的输入不做纠错。
4. 合法完整拼音不预生成纠错或简拼候选，避免 `nihao` 混入由一次编辑得到的 `niao`，同时保护正常输入延迟。候选生成器仍把纠错视为无精确词典命中时的后备路径。
5. 末尾补全按基础惩罚 1,500 分、每个补入字符 750 分降权；纠错路径每次编辑降权 6,000 分；多音节简拼按基础惩罚 8,000 分再叠加补字符惩罚。因此明确的一次纠错优先于宽泛简拼，例如 `niaho` 保持“你好”第一。同步候选生成阶段只要存在精确候选，第一候选必须来自精确拼音。
6. 所有解析和查词继续在 Core Service 候选工作链路执行，TSF 按键线程不扫描词库、不加载模型。协议暂不增加来源标记；匹配类型只在引擎内部用于排序与测试。
7. 基础排序至少从 32 个候选的内部池中选择首屏。保留最佳整段候选后，在单字与双字候选占用的槽位中，分数不低于 5000 的双字词最多优先 10 项（默认每页 5 项，即一至两页），随后是单字，最后是低权重双字词；用户词频仍可把双字词提升进优先区。三字及以上候选和前缀消费范围的既有位置语义不因此改变。
7. TSF 必须接收并处理空候选响应。请求尚未完成时显示 `…`，已完成但无结果时显示“无候选”，不得把空响应丢弃后无限保留加载状态。
8. 无显式 `'` 时，完整拼音路径优先使用最少音节数：`lan` 只按 `lan` 生成候选，`duo` 只按 `duo` 生成候选；需要更短边界时由用户显式输入 `'`。长度大于 1 的完整单音节不再补成更长音节，例如 `lin` 不占用 `ling` 候选位、`bin` 不占用 `bing` 候选位；单字母声母补全不受影响。多音节中与最短完整路径段数相同的不完整末段仍可参与补全，以保留 `zhonggu → zhong'guo` 等候选。

## 结果

完整词库验证中，`b` 返回“把/不/吧”，`nih` 包含“你好”，`zhongg` 首选“中国”；`wq` 包含“我去”，`ky` 首选“可以”，`gom` 首选“购买”并以“够吗”为第二候选。`niaho`、`nihap` 首选“你好”，`zhonggu` 仍以精确的“中古”为第一候选并提供补全的“中国”。精确输入的完整词库基准与改动前处于同一延迟量级；辅助输入的独立数据见 `docs/benchmarks/assisted-pinyin-2026-08-02.md`。

## 已知边界

- 本决策不是通用编辑距离或语言模型纠错；两处及以上错误、非相邻任意替换和显式音节边界内的纠错均拒绝。
- 能被完整合法拼音切分的输入不做纠错，即使该切分最终没有用户想要的词；后续若要放宽，必须采用“精确查词为空后再惰性纠错”的两阶段接口并重新测量延迟和误触发率。
- 简拼自身高度歧义，`wq` 等输入按词频和补全成本排序，不能无上下文固定为唯一词语；目标是把合理候选稳定纳入首屏。
- 补全候选当前不在候选窗标注来源。若未来增加标记，需要扩展候选协议并同时兼容 TSF UI Element 与独立候选 UI 进程。

## 回滚

移除 `ParsePath` 的匹配来源、补全/简拼/纠错扩展和相应候选惩罚，即可恢复只接受完整拼音路径的行为；词库格式、用户词频、IPC 消息和配置文件无需迁移。空候选状态反馈可以独立保留。
