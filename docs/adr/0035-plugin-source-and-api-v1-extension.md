# ADR 0035：插件来源与 API v1 扩展

- 状态：已采用
- 日期：2026-08-11

## 背景

P4 的插件安装仅在设置中心暴露 `.owopkg` 文件选择器，不利于本地开发，也不便于接收常见 `.zip` 发行物。插件服务名虽然已版本化，但缺少由 Core 维护的标准服务目录，调用方可能漏报敏感服务所需权限。

## 决策

1. 安装来源扩展为受限制的 `.owopkg`、受限制的 `.zip` 和本地文件夹；三者共用同一份 manifest、库存摘要、信任判断、知情授权、暂存发布和停用策略。
2. 文件夹来源先在预检阶段复制为不可变内存快照。只接受普通文件和目录，拒绝根目录或子项中的符号链接、junction 和其他重解析点。源目录不会成为运行目录。
3. 格式兼容不等于信任放宽。第三方、未验证和高风险来源仍须按精确库存摘要与权限列表单独授权，安装后保持停用。
4. 在 `plugin_services.h` 中维护 API v1 标准服务及其最低权限。Core 提交已知服务时自动注入最低权限，PluginHost 继续核对 manifest、活动版本和授权记录。
5. 保留开发者自定义的版本化服务名；自定义服务不能冒充 `owo.*` 服务的权限语义。
6. 新增候选变换、插件配置、通知、声明式设置页、模型资源和声音资源权限。需要普通 Win32 令牌的能力仍必须同时申请 `system.full_trust`。

## 影响

开发者可以直接选择构建输出文件夹测试插件，也能分发普通 `.zip`，但无法借此绕过签名、授权或沙箱。标准服务目录让扩展点保持可发现并把权限最低要求固化在 Core，而 payload 的具体 schema 继续按服务版本独立演进。

回滚时可移除文件夹选择入口和标准服务目录；已安装插件仍按版本化存储记录管理，不影响输入主链路。
